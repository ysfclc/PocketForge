# Security policy

Do not publish exploit details in public issues. Use GitHub private vulnerability reporting when enabled; otherwise contact the repository owner privately through GitHub. Never include credentials, signing keys or personal data in a report.

Scope includes hostile ZIPs, malicious build scripts/dependencies, compromised agents/connectors, leaked credentials, compromised CI runners and artifact substitution. See docs/security.

Security-sensitive changes require review. The repository owner coordinates acknowledgement, severity, remediation and disclosure; no response-time SLA is promised.
