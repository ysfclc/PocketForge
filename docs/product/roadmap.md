# Roadmap

0. **Keystone foundation — build gate achieved:** product/architecture/security contracts, agent roster and skills, Rust ABI scaffold, Android shell and Git-native CI. Evidence: current PR-head run 44793160312 built all three Rust Android ABIs, passed Rust tests/Clippy, assembled and verified the debug APK, and emitted an SBOM plus provenance attestation. Device feature acceptance remains separate.
1. **Local factory + GitHub workspace:** local project import, workspace, Project Passport, local toolchain/build, plus direct repository connection. **First local slice authored:** local workspace, SAF folder linking, folder inspection and scoped browsing, local Project Passport records and persistent Draft / Ready mission queue. First GitHub slice authored: connect and verify a repository using URL or owner/name, pin its default-branch commit, browse directories and preview text files; encrypted repository-scoped token storage uses Android Keystore; a reviewed single-file branch/commit/PR path is authored with stale-blob protection and separate commit/PR approvals. The current PR-head Android source compiled in CI run #109; folder/GitHub onboarding and strict commit pinning are built, with physical-device acceptance still pending. Remaining gate: prove the flows on-device; editable/exportable project context; multi-file patches; full diff/review workflow; branch/check history; and build/install two real Android projects through the local path. Local toolchain/build, cancellation and recovery remain unimplemented.
2. **Intelligence Nexus:** local model, frontier provider, capability router, durable mission execution and patch review. Gate: the same bounded mission lifecycle can carry out a real approved task against both a local project and a GitHub repository, with traceable changes.
   - **Architecture constraint:** one provider-agnostic mission loop and scoped capability gateway; local/frontier providers are intelligence only. No keyword-routed or per-example workflows. Acceptance must show real tool invocation, observed outputs, verified diffs/tests and durable recovery using the same mission path.
3. **Automation connectors:** Memo adapter and additional verified providers/capabilities. GitHub repository access is not deferred to this phase; it is a first-class project mode in Phases 1–2. Memo remains independent.
4. **Production loop:** diagnostics, tests, signing and artifact vault. Gate: a reviewed agent change becomes a tested signed APK with verifiable provenance through the local build path. Optional GitHub Actions builds are an additional execution backend, not a dependency.
5. **Expansion:** more project types, agent collaboration, sync and iOS evaluation. Each requires demand evidence, an ADR and a reversible rollout. iOS remains gated until bridge parity, signing ownership and macOS CI are explicitly approved.

Implementation status is not acceptance: every gate needs a built artifact, reproducible test evidence and device validation where applicable.
